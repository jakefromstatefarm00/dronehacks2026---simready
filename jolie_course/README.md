# jolie_course: Jolie's online path planner

Two ways to fly the same planner:

| File | Interface | Where | Status |
|---|---|---|---|
| **`upload_to_flyx.py`** | **native PX4**: publishes `/fmu/in/*` itself (Offboard, arm, land) | **FlyX lab only** | **Completed the whole course in FlyX (Jolie, 2026-11-07).** Frozen: do not edit. |
| **`upload_to_flyx_skybeta.py`** | Sky Beta | FlyX via `run.sh jolie_flyx`, and **the drone** | **The FlyX-proven file itself with only its PX4 I/O swapped** (its embedded mission and planner are byte-identical). Built by `build_skybeta_copy.py`; not yet flown |
| `jolie_course.py` | Sky Beta: `/skybeta/setpoint/pose` through the organizer's flight interface | FlyX via `run.sh`, and **the drone** | Isaac's Sky Beta node with the same turn changes ported; not yet flown |

## `upload_to_flyx_skybeta.py`: the proven file on the drone's interface

```
bash flyx_skybeta/run.sh jolie_flyx                  # FlyX / sim: flight interface + this + sim pilot
python3 jolie_course/upload_to_flyx_skybeta.py       # on the drone (the interface is up; the pilot arms)
```

`python3 jolie_course/build_skybeta_copy.py` regenerates it from `upload_to_flyx.py`, which is
never modified. It keeps every embedded module byte for byte, including her mission state
machine, the planner, and both turn changes. It replaces only the PX4 I/O (`skybeta_main.py.in`):
- **In:** cuVSLAM odometry, mapped ENU to NED with the flight interface's own REP-103 map, plus
  `/skybeta/state`.
- **Out:** `/skybeta/setpoint/pose`.
- **Never:** arms, changes mode, or lands. Her `LAND` state holds over the pad and is the pilot's
  cue.

Status topic: `/jolie_flyx/status`. Checked: the frame chain at arbitrary start poses (1 m up the
corridor lands 1 m along the start heading, to 1e-16), and ROS start-up and Ctrl-C under Jazzy.

## `upload_to_flyx.py`: the FlyX run that worked

```
python3 jolie_course/upload_to_flyx.py            # FlyX: flies (Offboard, arm, takeoff, course, land)
python3 jolie_course/upload_to_flyx.py --shadow   # plan and log only
```

You can also use it as the lab's "Run saved file". Reset world first, and start on the launch
mark facing up the first corridor. It uses the depth camera on `/camera/depth/image_raw`.
Ctrl-C / SIGTERM land. Journal: `./runs/flyx-<time>/journal.jsonl` (else `~/flyx-runs`).

**Do not run it on the drone, and do not run it alongside `flyx_skybeta/run.sh`.** It commands
PX4 directly. On the drone, the organizer's flight interface owns `/fmu/in`, and two setpoint
publishers fight. The file refuses to arm if it sees another setpoint publisher.

What it is: a single file generated by Jolie's `pathfinding/tools/build_single_file.py` from her
native FlyX program (`flyx/fly_pathplan.py` + `flyx/mission.py` + the planner) at commit
`7a737e0`, **plus two changes that are not in any committed source yet**:
1. **Keep moving while turning.** The drone stops and turns in place only if the route is more
   than 60° off its nose (the planner default is 30°). It used to stop 21–26 times per flight.
2. **Slow carrot while turning.** The carrot shrinks from 0.5 m to as little as 30 % while the
   nose is still turning toward the route, so the drone slows through corners instead of swinging
   wide.

The native sources were removed from `pathfinding/` when the repo moved to the Sky Beta contract.
They are in git history at `7a737e0`. To rebuild this file, Jolie needs to push the sources with
those two changes.

## `jolie_course.py`: the same planner on the drone's interface

```
bash flyx_skybeta/run.sh jolie          # FlyX / sim: organizer's flight interface + this + sim pilot
python3 jolie_course/jolie_course.py    # on the drone (the interface is already up; the pilot arms)
```

It runs `pathfinding/flyx/pathplan_mission.py`, which is generated from
`pathfinding/ros2/dronehacks_pathplan/` (Isaac's Sky Beta node) and `pathfinding/pathplan/`.
That node carries the FlyX-proven behaviour:

| Behaviour | |
|---|---|
| planner and its process | the same planner, in its own low-priority process |
| depth | placed at the capture-time pose; frames with no matching pose are skipped |
| heading | yaw rate capped at 0.25 rad/s |
| odometry pauses | the last setpoint is held |
| landing | it centres over the pad first |
| CPU | single-threaded executor |
| turning | **both changes above**: turn-in-place at 60°, and the carrot slows while turning |

On top of that it adds what the drone needs:
- the frame is anchored to the measured start pose;
- it never arms or lands;
- it holds and reports `ready_to_land` for the pilot.

| | Topic |
|---|---|
| reads | `/visual_slam/tracking/odometry`, `/skybeta/state`, optional depth image + `camera_info` |
| writes | `/skybeta/setpoint/pose`, `/dronehacks_pathplan/status` (JSON: `state`, `ready_to_land`, `cleared`, ...) |

Depth: in FlyX use `/camera/depth/image_raw` (`run.sh` passes it). The drone has no depth topic,
so leave `depth_topic` empty and it flies the published map only. Parameters:
`pathfinding/ros2/dronehacks_pathplan/README.md`. Edit the sources, then rebuild with
`python3 pathfinding/tools/build_single_file.py`. Tests: `cd pathfinding && python3 -m pytest -q tests`.
